# Agora creation recovery and original FPMM previews

2026-09-10. No economic contract, fee, payout, proof profile or certificate change.

`src/create-flow.mjs` freezes the reviewed wallet, registry, registration calldata, funding and fee for the composite registration → pool → approval → funding flow. Each submitted transaction hash is saved before receipt waiting. Resume first checks that receipt and the expected event from the exact contract; it never blindly sends the same uncertain funding transaction again. Completed steps are skipped. Wrong wallet/registry and successful replacement receipts without the expected event fail closed. The UI lists statement/pool/receipts and offers an explicit resume or opens the already registered statement. No automatic background transaction is sent.

The checkpoint is tab-local and cleared on wallet identity change. It is not a durable cross-device transaction manager. After reload, open the registered statement from Explore: Liquidity includes an explicit create-missing-pool control and independent funding. A creation with known submitted but unconfirmed/unrecognised receipt must be inspected before continuing; no claim that closing the tab cancels the transaction. Forced partial-creation browser recovery remains untested: this pass deliberately created no extra market.

`sdk/liquidity-preview.mjs` reads original FPMM reserves, supply, owner shares and `feesWithdrawableBy` at one block. With no distribution hints, original funding uses `weight=max(reserves)`, `retained[i]=floor(T*reserve[i]/weight)`, `LP=floor(T*supply/weight)` and returns each residual outcome. Initial funding creates equal outcomes and LP shares. Removal returns `floor(reserve[i]*shares/supply)` plus **all** accrued owner T fees: original `_beforeTokenTransfer` withdraws those fees before burn. All math is bigint with uint256 multiplication bounds. LP shares are never labelled T.

The browser requires Refresh LP preview before funding/removal, shows exact YES/NO and shares/T, and compares a fresh projection before submission. The pinned FPMM funding ABI has no minimum-output parameter, so the UI explicitly discloses possible changes before mining. It does not claim a slippage guarantee. The snapshot remains labelled with its observed block after a transaction; refresh to see new estimates. SDK `previewLiquidity` exposes the same projection. Split/merge checks positive exact amounts and actual same-block T/YES/NO balances, shows maximum matched outcomes and disables insufficient merge.

Validation: 19 targeted tests cover interruption after registration, funding receipt uncertainty, owner mismatch, zero funding, missing expected replacement event, original integer floors/overflow/all-fee withdrawal, complete-set insufficiency and wallet/import regressions. Vite production build passed under the reviewed1GiB guard:1.767s,404111928B peak. Afterwards a conservative missing-event retry retention and busy clear-button gate were tightened; the19 tests including actual Vue SFC compilation passed again. No second production build was needed for those two small changes. Existing bundle-size warning remains.
