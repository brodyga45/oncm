# Vault: статическая сверка 20 пользовательских сценариев

Дата: 2026-09-10. База — `../../docs/user-scenarios.md`, действующие web/SDK/API и Solidity. Это проверка связи действия с реализацией, не обещание успешного криптографического end-to-end. Текущая новая Anvil-сеть сохранена; рынки/доказательства ради этой сверки не создавались. Все упоминания строк относятся к состоянию до последующих небольших правок; имена функций являются устойчивыми ориентирами.

`Связан` означает наличие конкретного выполняемого пути. `Частично` означает реальный недостающий шаг исходного пользовательского сценария. Ни одна строка сама по себе не означает, что реальный zk smoke прошёл. Сейчас expensive proving выключен; доступного настоящего сертификата для финального smoke нет. Это отдельная общая зависимость US-001/004/005/017, а не объяснение остальных пробелов.

## Реальные пробелы и конкретные изменения

1. **G1 — публичная постановка (US-001/004/005/015).** `web/App.svelte`, раздел `Формальное содержание`, и `server/index.mjs` `/api/export/:id` сейчас не дают source любого публичного statement. Нужны отдельный authenticated publish endpoint с явно переданным текстом, публичное чтение и файл-хеши; UI должен различать source автора и goal commitment, подтверждённый verifier. Нельзя извлекать source из чужих private jobs по совпадению goalHash. Это функциональный пробел, не отсутствие сертификата.
2. **G2 — переносимый package (US-013).** `/api/export/:id` возвращает evidence JSON и лишь свои jobs; отсутствуют отдельный Challenge/Solution, lake config/lock и formalization metadata template. Нужен генератор downloadable files с происхождением, pinned toolchain и инструкцией независимой проверки; Palomar compliance требует отдельной валидации, а не смены расширения JSON на zip.
3. **G3 — LP preview (US-002/019).** `sdk/index.mjs initialize/join/exit` и `web/App.svelte` `Управление ликвидностью`: реальные Router queries исполняются внутри отправки, результат пользователю до approvals не виден. Выделить quoteJoin/quoteExit; показать каждый token/expected/max-or-min; при подтверждении использовать именно эти пределы и повторно запросить quote после изменения input. Stress scenario — оценка settlement inventory, не execution quote.
4. **G4 — типизация новых operators (US-007).** `registerOperation` принимает ID+bytes, details показывают spec hash/bytes. Готовый модуль `ResolvedWithinWindowOperator` существует, но произвольная спецификация не превращается в форму автоматически. Для общего механизма требуется versioned off-chain schema/decoder с проверенным ID; raw SDK уже работает.
5. **G5 — governance review (US-009/018).** `server/index.mjs /api/governance`, `web/App.svelte govCall/moveGov`: нужны proposalEta, hasVoted(address), историческое ABI-decoding/registry diff, proposal discussions и UI value/multicall если обещать все SDK-возможности в вебе. Сейчас полные calldata можно прочесть вручную, а contract lifecycle существует.
6. **G6 — промежуточные комиссии (US-011).** `web/App.svelte loadClaims` читает только warehouse.balanceOf; `sdk/index.mjs` collect/distribute/claim не дают preview upstream. Нужны real controller claimable creator-fees и ERC-20 balance каждого immutable Split по активу; не конвертировать их в воображаемый T. Отдельно от уже credited Warehouse claims.
7. **G7 — Palomar navigation/environment (US-012).** `server/palomar.mjs palomarRecent/palomarSnapshot`, `web/App.svelte` Palomar picker: theorem_names[0] и recent.json. Нужны declaration/version выбор и явная оценка совместимости профиля; импорт не устанавливает все dependencies и не означает принятую proof goal.
8. **G8 — смена injected identity (US-014).** `web/App.svelte connect/onMount/wallet-panel`: привязать accountsChanged/chainChanged к сбросу signer, SIWE и owner-only state, добавить Disconnect. Не просить подпись автоматически и не переносить сессию старого адреса на новый.

## Исправления и границы проверки

- US-003: `sdk/swap-limits.mjs` фиксирует displayed minOut/deadline до approvals; при явно переданных пределах quote callback вообще не вызывается. Старый SDK signature остаётся совместимым, но его convenience quote также фиксируется до approvals. Original Router проверяет лимиты при исполнении.
- `test/swap-limits.test.mjs`: 3 лёгких теста callback orchestration passed, включая изменение времени/цены во время approvals и отказ до approvals при expired/invalid limits. Ни RPC-рынок, ни proof/mock verifier не создавались.
- UI: собственный job JSON download и source restore, expected outcome и timezone производных, честное название evidence export. Svelte compiler прошёл без предупреждений. Это не ручной browser test и не live swap.
- Документация восстановления и проверка сохранённой Anvil state находятся в README и VALIDATION. Retention локального explorer ограничен параметрами devnet; block history построена из настоящих RPC blocks/receipts/logs. Transfer deltas не называются полной исторической переоценкой portfolio.

## Обновление после исправлений

Таблица выше сохраняет результаты первоначального аудита; приоритетные пробелы затем исправлены в этой же работе:

- **G1:** `server/publications.mjs`, endpoints `/api/statements/:id/publications`, `web/PackageEditor.svelte`. Источник публикуется только явно переданным запросом с publish=true и SIWE-author, подтверждённым Registry; читаемые Challenge/Solution, ревизии и SHA-256 показываются публично. Неизменённый semantic commitment отображается отдельно. Соответствие source этому commitment не выдаётся за установленный факт до реальной проверки; публикация необязательна, её отсутствие обозначено.
- **G2:** `preparePackage` / `packageZip`, `/api/packages/prepare|download`, community SDK и редактор. ZIP действительно содержит отдельные Lean-файлы, pinned toolchain, Lake config/optional lock, метаданные, runner input и инструкции. Содержимое проверено распаковкой fflate. Это переносимый минимальный Lake package; сторонние библиотеки не vendored, автоматическая совместимость Palomar/Lake imports не обещана.
- **G3:** `sdk/index.mjs quoteLiquidity`, `sdk/liquidity.mjs`, web `getLiquidityQuote/executeLiquidity`. Initialize/join/exit имеют отдельные расчёт и подтверждение. Показаны реальные токены и exact/max/min amounts, BPT, блок. SDK проверяет привязку снимка к pool/actor/token order/amount; при переданном снимке не пересчитывает пределы. Initialization использует оригинальную computeInvariant, поскольку только standard 18-decimal tokens поддерживаются coordinator.
- **G6:** `sdk.revenueSnapshot`, `sdk/revenue.mjs`, `web/RevenuePreview.svelte`. Block-pinned состояния Vault/Controller/каждого epoch Split/Warehouse доступны по этапам, с точными исходными активами. Начальный live snapshot подтвердил epoch1/T=0 при block30. Формула pending creator использует ставки и aggregate percentage самого Controller с его округлением; успешный funded-pool UI smoke ещё не выполнен.
- **G8:** `web/App.svelte clearWalletState/disconnectWallet/connect/onMount`. Добавлены logout и injected identity event handlers. Private editor/job/certificate state очищается при отключении/смене адреса, серверная история не удаляется. При первоначальном подключении анонимный несохранённый draft сохраняется.

Остались **G4** (универсальные типизированные operator формы), **G5** (более полная governance review/ETA/обсуждения), **G7** (Palomar multi-theorem/version navigation и широкий environment support). Дополнительно подтверждение source→goal для публикации всё ещё зависит от реальной проверки, а криптографический market→settlement smoke — от настоящих certificates. Мы не устраняли эти ограничения переименованием metadata в доказательство.

Проверка после правок: 21 лёгкий test passed; live SIWE API подготовил/скачал ZIP 5092 bytes без сохранения или исполнения источника, anonymous получил отказ; Svelte build 1.21 s. Все новые upstream view methods найдены в существующих ABI. Web и API HTTP200. Перезапущен только API после проверки, что пять jobs terminal; deployment/community/policy SHA-256 до и после одинаковы. Chain block30 и 0 markets сохранены. Подробности в VALIDATION.
