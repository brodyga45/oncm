# Governed monetary policy — SDK/UI candidate

This implementation implements the typed browser/SDK side of US023 for the explicitly selected V2 deployment. It does not upgrade legacy T in place. In the existing genesis-only deployment the panel reads actual T supply and explains the unsupported capability; no mint controls are active. This pass made no deployment, issuance, reward claim or financial transaction. Contract ownership and V2 deployment are separate reviewed work.

## User flows and bindings

- Initial T access: enter an exact recipient and decimal T amount, prepare an ordinary Governor proposal for `TrueTokenV2.mint`. Review shows current and hypothetical supply. Mint is called only by the existing Timelock execution path; an EOA cannot mint directly. T issuance does not create MEMBER votes.
- New program: select/discover its actual meter and official pool, enter local calendar dates, exact budget and fixed remainder recipient. The review exposes local timezone, UTC and exact Unix seconds. Preparation builds the ordered `mint(RewardBudget) → createProgram(expectedId, …) → configureProgram` batch. CAS prevents a concurrent program from consuming the reviewed ID. There is no retroactive program budget edit.
- Trade weight modes are gross T-leg volume, or EXACT_IN T-input fee weight. The latter excludes sells/T-output and EXACT_OUT swaps. Volume mode makes no self-trading resistance claim. Each new user's hook is discovered through the pinned coordinator and original Vault registration, including exact constructor links and original Router runtime identity; it does not require adding fixture addresses to a static catalogue.
- LP rewards require BPT locking until program end; exact BPT approval/staking uses account, network and input fences. Claim pays the connected participant, never a substituted recipient. Program read pages show actual weights, budgets and claimable amounts. After the claim deadline, a separate Prepare → Confirm control closes the program permissionlessly. It previews the exact original remainder recipient and `budget - paid` (including zero), verifies the actual original close return through `eth_call`, and rechecks state and wallet/form bindings before sending. No new recipient can be chosen.
- Fee preparation changes total pool swap fee, creator fraction, or global protocol fraction via governance. Total swap fee is not labelled an LP-only fee. Every collected V2 protocol/creator stream goes to the active beneficiary split, with governance receiving only its own share. V2 collection calls `collectAll`; legacy retains creator-only `collect` and explicitly labels the difference. Changing the global default does not silently change existing cached pool rates: a separate Prepare → Confirm path calls the original permissionless controller update for one official pool, refuses override/no-op pools, and displays actual receipt-block old/new rates.

The SDK requires an explicit `vault-monetary-v1`, `status: deployed`, `protocolVersion: 2` descriptor with actual T/RewardBudget/Timelock bindings and runtime pins. It re-reads authority, counter, supply, fee and wallet/form bindings before Governor proposal. Single mint/fee calls receive actual Timelock `eth_call`; ordered program preparation **does not claim full batch execution simulation**, because separate calls cannot carry the mint state into program creation. Normal queued Governor execution provides the whole ordered batch simulation.

## Runtime selection review

`server/runtime-version.mjs` selects separate `deployment-v2`, `abis-v2`, `social-deployment-v2`, `community-v2` and `publications-v2` JSON files. Legacy names remain unchanged. The new social resolver must bind the new StatementRegistry; copying the old social descriptor is rejected. `social/deploy.mjs` reuses the pinned artifacts, verifies existing descriptors or deploys the three components additively. It does not compile or reset the market chain. Startup checks the full API protocol graph, rather than accepting a common chain ID or Governor as proof that the right version is served.

For the parent-owned switch, keep the existing Anvil and Vite processes, first verify the API listener's PID/cwd and that all old proof jobs are terminal, then stop **only** that API. In the Vault directory, the explicit version commands are `VAULT_PROTOCOL_VERSION=2 node social/deploy.mjs` (additive transactions if absent, read-only verification if present) followed by `VAULT_PROTOCOL_VERSION=2 node server/index.mjs`. The existing Vite proxy points at the same 4173 API and can remain running. Afterwards verify `/api/config` reports V2 T/registry/social identities and reload the UI; in-memory SIWE sessions are intentionally lost. Neither `npm dev` nor changing ports is needed for this same-chain switch. This review did not stop/start any process or execute the deployment commands.

## Completion patch validation

After the first live root-owned issuance cycle, the missing close and existing-pool fee synchronization conveniences were implemented. [Completion evidence](evidence/monetary-policy/completion-validation.json) pins the updated sources. All 24 focused tests passed in 245.8 ms, followed sequentially by Vite in 1.93 s under the same 768 MiB / 60 s guard. The resource report retains exact whole-tree peak/time and cleanup result. The earlier 17-test/build record remains historical evidence for its pinned earlier sources, not a claim to cover these later edits.

UI controls: **Проверить закрытие программы N** → exact remainder review → **Закрыть программу и вернуть остаток**; and **Проверить обновление ставки пула** → old/global/target review → **Обновить protocol ставку этого пула**. A cancelled or changed wallet/input invalidates the prepared operation. Override and already-current pools show the original reason without a send button. SDK return values expose the fee-sync receipt and rates at that receipt's block. These controls are build/unit verified; this patch did not itself execute them in the browser.
