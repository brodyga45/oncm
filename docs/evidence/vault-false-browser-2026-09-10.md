# Vault: настоящий FALSE-цикл через браузер

Цепь 31373, persistent instance `554c825d-6813-43bf-9bf0-6ede06acff4d`, http://127.0.0.1:5173/. Проверка выполнена через формы сайта, публичные локальные кошельки Account 0 (создатель/LP) и Account 1 (трейдер). Новые ZK-вычисления не запускались: импортированы существующие настоящие сертификаты CI5 и CI6.

Производное: `0xafd09c0dbc270d6fc11dedcb31667639c747e33531e4c554305b20475d6a82b2`. До базового разрешения на блоке 160 нажатие «Разрешить по состоянию chain» отклонено, блок не изменился. Контрактная защита сработала, но UI показал непонятное `execution reverted (unknown custom error)`; исправление читаемого сообщения передано агенту, повторная проверка требуется отдельно.

Сценарный калькулятор на блоке 154 для Account 0 правильно показал inventory 20 T + 80 NO, результат True → 20 T / False → 100 T. После смены кошелька обнаружено сохранение старого расчёта при корректном обновлении основного баланса LP. Это подтверждённый UI-дефект, а не завершённая проверка изоляции расчёта; исправление и повторный проход фиксируются отдельно.

После False сайт убрал форму swap и отключил пополнение; пропорциональный выход остался доступен. Точные receipts, gas, адрес пула и суммы в wei собираются независимым RPC-отчётом. Округлённые числа выше не заменяют этот отчёт. В данном проходе не проверены новые выплаты протокольной комиссии, deadline-ветки или публичная L2.

## Независимые данные и повтор после исправлений

[RPC evidence 148–169](../../implementations/vault/evidence/false-cycle/browser-rpc.json) подтверждает payout базового `[0,1]` и производного `[1,0]`. Трейдер получил `1.365909020954537360 T`; выход LP вернул `21.447315823958655385 T` и `78.633090979044165677 NO`; последующее погашение LP дало `98.633090979044165677 T`. У обоих кошельков позиции стали нулевыми. Это не означает нулевых глобальных резервов: остаются accrued fees и минимальная заблокированная LP-доля. Исходный verifier — view-функция без события; доказательством транзакционного исхода служит событие реестра и calldata, а не выдуманное событие verifier.
