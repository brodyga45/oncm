# Профили и обсуждения утверждений

**Последнее решение пользователя, 2026-09-10: весь социальный слой переводится ончейн и добавляется личный блог каждого участника.** Актуальные границы и приёмка — [onchain-social.md](onchain-social.md). Описанная ниже офчейн-модель и её SIWE API сохранены как история предыдущей реализации; они больше не являются целевой архитектурой социальной части.

Уточнение пользователя 2026-09-09: профиль по кошельку, по аналогии с Polymarket; обсуждения с голосами и подъёмом полезных сообщений, по аналогии с Math Stack Exchange. Требование включено во все три реализации. Конкретные правила ниже — выбранные детали первой реализации; их можно менять независимо от контрактов рынков.

## Граница доверия

Профиль, комментарий, ответ и голос хранятся офчейн. Чтение публичное. Запись требует проверенной SIWE-сессии; подключение кошелька само по себе не аутентифицирует автора. Не нужны отдельные логин и пароль, газ или токены для голосования. Ончейн-правила доказательств, выплаты, AMM и голоса governance от этих данных не зависят.

Ключ профиля — нормализованный EVM-адрес в пределах приложения. Имя — подпись к адресу, а не подтверждение личности и не уникальное имя аккаунта. Адрес остаётся доступен рядом с именем и в профиле. Разные адреса не объединяются автоматически. Один адрес не означает одного человека: рейтинг сообщества не является защитой от Sybil-атак и не даёт протокольных прав.

## Данные и контракты сервиса

```ts
type Profile = {
  address: string; displayName: string; bio: string; updatedAt: string;
};
type Comment = {
  id: string; chainId: number; registry: string; statementId: string;
  author: string; body: string; parentId: string | null; createdAt: string;
  score: number; myVote: -1 | 0 | 1;
};
type Vote = { commentId: string; voter: string; value: -1 | 1 };
```

Логический API (конкретные URL описывает SDK каждой сборки):

```text
getProfile(address) -> Profile + public comments/activity
updateMyProfile(session, {displayName, bio}) -> Profile
postComment(session, statementRef, {body, parentId?}) -> Comment
listComments(statementRef, {sort: top|new, cursor?}) -> comments
setCommentVote(session, commentId, -1|0|1) -> {score, myVote}
```

Адрес изменяемого профиля и автор записи берутся только из сессии. `parentId` должен существовать в том же обсуждении; ответ не переносит текст в другой рынок. На хранении действует уникальность `(commentId, voter)`. Голос `0` удаляет прежний голос; повторная отправка `1` не добавляет ещё один плюс, смена `1 → -1` уменьшает сумму на два. Самоголосование отклоняется сервером. Итог вычисляется из голосов, а не из присланного клиентом счётчика. Обновление голоса и результата должно быть атомарным.

Режим «Популярные» сортирует верхний уровень по сумме голосов убывающе, затем по времени создания и ID для стабильного порядка. Ответы остаются под родителем и идут по времени. Режим «Новые» сортирует верхний уровень по времени убывающе с ID как дополнительным ключом. Лайк текста не подтверждает корректность математики.

Текст отображается как экранированный текст либо безопасный Markdown; HTML/скрипты автора не исполняются. Приложение ограничивает длину имени, биографии и сообщения. Ввод изображений и внешних avatar URL не обязателен: начальный аватар можно строить из адреса без загрузки стороннего контента. Полноценная репутация, значки, принятый ответ и модераторские выборы пока не входят в это уточнение.

## Айсберг пользователя

| Веб / SDK | Под поверхностью | Наблюдаемый результат |
| --- | --- | --- |
| Кошелёк → «Мой профиль» → меняет имя и описание → сохраняет. | При необходимости SIWE; API берёт адрес из сессии и сохраняет профиль. | Имя появляется у сообщений; адрес сохраняется как идентификатор. После обновления страницы данные остаются. |
| Задача → «Обсуждение» → публикует комментарий. | API проверяет сессию, существование контекста и ограничения текста. | Сообщение от собственного адреса, без транзакции в блокчейне. |
| У сообщения нажимает «Ответить». | `parentId` проверяется на принадлежность той же задаче. | Ответ под исходным сообщением, с кликабельным профилем автора. |
| Другой кошелёк нажимает ↑, затем ↓ или отменяет голос. | Сервер записывает один голос для адреса, изменяет/удаляет его и пересчитывает сумму. | Счётчик и собственный выбранный голос согласованы после обновления страницы. |
| Выбирает «Популярные» или «Новые». | API возвращает выбранный устойчивый порядок. | Полезные сообщения поднимаются по голосам, ветки ответов сохраняют контекст. |
| Нажимает имя автора. | Публичное чтение профиля по адресу. | Адрес, имя, описание и доступная публичная активность. |

## Приёмка

Проверяем отдельно для каждой реализации: два разных кошелька, редактирование только своего профиля, сообщение и ответ, плюс/минус/отмена/повтор голоса, отказ самоголосования, порядок «Популярные / Новые», сохранение после перезапуска API. Подмена поля `author` или `address` не позволяет действовать за другого человека. Отказ подписи и смена кошелька не оставляют права старой сессии у нового адреса. Состояние утверждения и баланс T до и после социальных действий одинаковы.
