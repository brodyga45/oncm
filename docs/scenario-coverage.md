# Покрытие сценариев компонентами и контрактами

Исходная проектная карта от 2026-09-09, статус уточнён 2026-09-10. Этот документ дополняет [пошаговые пользовательские сценарии](./user-scenarios.md), а не заменяет их. Обозначения A/B/C относятся к [трём архитектурам](./architecture-options.md). Ниже описаны требования к покрытию, а не результаты тестирования. Три реализации уже существуют и запускаются независимо; YES/NO и полные наборы входят в выбранную экономику. Полнота Palomar-импорта/экспорта оценивается отдельно по фактическим ограничениям каждой реализации.

Авторитетные записи текущей проверки: [программа реализаций](./implementation-program.md), [ручной журнал](./manual-validation.md), [реальные сертификаты и CI](./ci-proof-validation.md), а также `VALIDATION.md` и доступные `COVERAGE-AUDIT.md` внутри каждой реализации. Наличие маршрута web/SDK/контракта не считается пройденным пользовательским сценарием. Полный Lean → zk → EVM → settlement пока не подтверждён; исходные требования не сокращаются до уже пройденных проверок.

## Общие пути продолжения после ошибок

| Ситуация | Что видит пользователь и как продолжает | Требование к слоям |
| --- | --- | --- |
| Отказ подписи / недостаточно gas | Действие не отправлено; можно повторить после исправления | Не создавать фиктивный успешный статус в БД |
| Approval прошёл, основная операция нет | Показать завершённое разрешение и оставшееся действие; перечитать баланс/котировку | План возобновляется по фактическому chain state, а не слепым повтором всех tx |
| Транзакция включена, индекс отстаёт | Показать receipt и временно читать контракт напрямую | Индекс хранит observedBlock; деньги не зависят от него |
| Реорганизация цепочки | Подтверждение возвращается в ожидающее/неподтверждённое состояние | Ponder/RPC восстанавливают индекс; offchain комментарии не откатываются с индексом |
| Lean прошёл, zk-job не завершился | Диагностика и скачиваемый входной пакет; повторить или запустить локально | Идемпотентный job, pinned versions, отсутствие ручного обхода verifier |
| Доказательство для другой цели/профиля | Явное несовпадение с ожидаемой постановкой | Контракт отвергает claim; UI-проверка не является единственной защитой |
| Срок наступил, запись не сделана | Кнопка «Разрешить» или SDK finalize | Permissionless транзакция; историческое время исходного резолва сохраняется |
| Доли изменились до применения предложения | Таблица помечена устаревшей, нужно новое предложение и согласия | baseVersion проверяется контрактом, старые approvals не переносятся |
| Beneficiary потерял ключ | Доля сохраняется; использовать предусмотренный самим кошельком recovery, если он есть | Исключение из обязательного согласия пользователя не задано |
| Описание/Palomar/наш API недоступны | Ссылка на доступный пакет/локальный импорт; прямые контрактные действия | Комментарии и внешний каталог не становятся условием redeem/governance |

## Операционные функции финального продукта

Не вводят новые денежные роли или разрешения, но необходимы для обсуждённых сценариев:

- Запуск/восстановление индексатора из deployment manifest и chain history; сверка прямого RPC и каталога.
- Исполнение и повтор Lean/zk jobs; квоты и видимое согласование стоимости удалённого proving до запуска платной работы. Бесплатный неограниченный prover исходным требованием не задан.
- Публикация доступных snapshot/зависимостей, проверка хэшей, выгрузка пользовательского пакета для независимой работы.
- Permissionless вызовы resolveDerived и distribute; отсутствие нашего keeper может задержать запись, но не даёт ему власть выбирать результат.
- Подготовка нового релиза профиля/оператора через тот же US-009: manifests, проверочные артефакты, область применения и отображаемое изменение правил.
- Модерация видимости комментариев по принятой политике; модератор не получает роль CTF oracle или право распоряжаться активами.

## Проверка полноты требований

R-001–R-010 покрываются US-001–US-011, US-018–US-020; R-011 отражён выбором готовых частей во всех строках. R-012–R-014 покрываются общим SDK, границей on/offchain и US-014–US-018. Palomar остаётся опциональным расширением US-012/013. Критерии измерений, адреса зависимостей и этапы реализации находятся в [плане](./delivery-plan.md).
