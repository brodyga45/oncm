# Три независимые реализации

**Изменение задачи 2026-09-10:** по прямому решению пользователя дальнейшая разработка и приёмка сосредоточены на Vault; Agora/Exchange заморожены. [Основание выбора и распределение всех агентов](vault-focus.md). Ниже сохранена история первоначальной программы; требование довести все три одновременно больше не является активным критерием.

Дата начала: 2026-09-09. Источник: пользователь поручил выбрать три контрастные архитектуры, зафиксировать решения в отдельных подпапках, параллельно реализовать их с максимум шестью подагентами (по два на вариант) и вручную проверить все сценарии на тестовом блокчейне. Активная цель создана в задаче.

Дополнение активной цели от2026-09-10: governance как отдельный выгодополучатель с внутренним принятием согласия на уменьшение своей доли и распоряжением доходом. [US-022 и контрактная модель](governance-beneficiary.md) реализуются во всех трёх папках; прежние проверки EOA-получателей этого не заменяют.

Дополнение US-023: [эмиссия, стимулы и комиссии под управлением governance](governed-monetary-policy.md), без обязательного внешнего торгового пула. Текущие genesis-only T не удовлетворяют этому новому требованию; интеграция/миграция входят в оставшуюся работу.

**Обязательное уточнение пользователя:** недостаточно различать real/mock — требуется довести настоящую ончейн-проверку Lean-доказательства до рабочего состояния во всех трёх реализациях. Это жёсткий критерий активной цели. Координатор отвечает за работающий proof toolchain и его интеграцию, ведущие — за вызов настоящего verifier без обходного ручного назначения исхода. До выполнения этого пункта вся цель не считается завершённой.

Все три сохраняют T/полные наборы YES/NO, permissionless создание, точные Lean-цели, доказательный адаптер, производные по записи/сроку, правило согласий каждого теряющего долю и отдельные выплаты прошлых эпох. Изменения незафиксированных деталей разрешены при описании причины. Не заменяем три AMM одной собственной формулой под тремя темами UI.

## Независимость

Каждая папка содержит свой manifest/lockfile, исходники/ABI, deployment scripts, SDK, сайт, API, тесты и README с одним документированным запуском. Нет runtime-импортов из соседней реализации и зависимости от общей запущенной службы проекта. Локальные state/data/logs/chain адреса раздельны. Общая работа над доказательным инструментарием может копироваться/пакетироваться как pinned open source-зависимость, но каждая папка запускает свой экземпляр.

Кошелёк пользователя поддерживается через EIP-1193. Для ручного тестирования допускается явно обозначенный devnet-wallet с публично известными тестовыми ключами, строго ограниченный собственным chainId/RPC; реальные средства/приватные кошельки не используются.

## Команда и контроль

Пользователь запросил максимум шесть подагентов: по два на вариант. Фактический лимит инструмента — три подагента плюс координатор; попытка создать четвёртого получила `agent thread limit reached`. Поэтому три ведущих реализуют варианты параллельно, затем перекрёстно проверяют чужие варианты. Это ограничение среды, а не шесть якобы созданных агентов. Координатор ведёт proof toolchain, общий контроль отличий и ручные проверки браузером. Не создаём дополнительные пользовательские задачи.

Ведущие работают только в своей подпапке, самостоятельно организуют front/backend и сверяют оригинальные исходники. Второй участник пары проверяет контрактные инварианты, сценарии, независимый запуск и исправляет найденные дефекты. Общий coordinator может переносить помощь к отстающей реализации после завершения другой.

## Критерии завершения

**Изменение объёма пользователем 2026-09-10:** встроенный заказ/вычисление zk-сертификатов из сайтов исключены из текущего этапа и отложены. Пользователь подготавливает сертификат внешне; три сайта должны импортировать его, проверять и выполнять регистрацию/резолв через кошелёк. Это не отменяет настоящую onchain-проверку, обе стороны выплат, остальные пользовательские сценарии и авторские функции. CI уже дал четыре настоящих сертификата; автоматическая интеграция CI/remote-provider в сайт остаётся инструментарием будущего этапа; их интеграция в сайты больше не является критерием текущего завершения. Нативная проверка Lean может оставаться.

1. Три разные реализации независимо собираются и запускаются по README на трёх локальных блокчейнах.
2. Настоящие транзакции создания/LP/trade/settlement/governance/согласий/выплат; реальные receipts и балансы. Клиентская анимация и записи в БД не заменяют контракты.
3. Все23 US имеют реализацию либо явно описанную равнозначную вариацию выбранной архитектуры; proof/Palomar/SDK пути проверены своими артефактами, не фиктивным успехом.
4. Каждая реализация вручную прокликана в браузере; журнал содержит шаг, результат, tx/артефакт и найденные/исправленные дефекты. Автоматические тесты дополняют эту проверку.
5. Проверены неверные сертификаты/цели, выплаты, лимиты сделок, согласия всех теряющих и сохранение старых выплат.
6. Реальный Lean/zk-путь отделён от экономических тестов с mock verifier. Mock допустим как явно тестовый harness; он **не закрывает** требование Lean → zk → onchain и не позволяет объявить всю цель завершённой.
7. Первый сквозной smoke: опубликовать цель, создать рынок, предоставить ликвидность, совершить сделки, представить настоящее доказательство, разрешить рынок и погасить выигравшие позиции. По каждому действию доступны блок, timestamp, tx hash, события и изменения балансов. Пользователь разрешил заменить Великую теорему Ферма компактным результатом; первоначально рассматривался `Nat.add_comm` из Lean4.33.1, затем для настоящего лёгкого smoke использован perf05: `∀ P : Prop, P → P` и опровержение `∀ P : Prop, P`. Это не утверждение о готовности поддержать весь экспорт FLT.

## Дополнительные возможности

**Новое обязательное уточнение 2026-09-10:** профили, комментарии/ответы, голоса и история правок во всех трёх вариантах переводятся ончейн; добавляется личный блог каждого кошелька. Полный текст должен быть доступен из сети. Это обязательная часть, не один из дополнительных авторских бонусов. [Контракт новой социальной части и приёмка](onchain-social.md). Старые офчейн-проходы не закрывают эту новую приёмку.

Пользователь разрешил 2–3 авторские фичи на реализацию. Ведущие самостоятельно выбирают их, согласуют различия между вариантами и описывают в `EXTRA-FEATURES.md` своей папки. Эти возможности дополняют обязательные сценарии и тоже требуют работающего UI/SDK и проверки. Профили, ответы и рейтинг комментариев из отдельного уточнения пользователя — общая обязательная часть, а не авторский бонус.

## Статус

**Текущий срез 2026-09-10:** получены настоящие Groth16 сертификаты perf05 для регистрации и доказательства `∀ P : Prop, P → P` в GitHub CI. Оригинальный EVM verifier принял оба и отклонил изменённые claims. В Vault профиль допущен через обычный Governor/Timelock; вручную пройден рынок91 → split/merge → Balancer liquidity102 → buy105/sell108 → ZK resolution110 → trader redemption112 → LP exit114/redemption117. Производное `ResolvedAs(base,False)` разрешилось какFalse118. Блок110 и decoded CTF/registry events раскрыты в браузере. Подробности и границы — в [ручном журнале](manual-validation.md) и [CI evidence](ci-proof-validation.md).

**Дополнение того же дня:** в Agora также пройден настоящий true lifecycle: Safe schedule29 → local time block30 → Timelock execute31 → регистрация32/пул33/взнос100T35 → второй LP20T37 → покупка39/продажа41 → настоящий ZK resolution42 → trader redemption43 → LP fee44/exit45/redemption46. В браузере раскрыты оба события resolution42 с payout[1,0]. В Vault дополнительно собраны и распределены реальные комиссии, оба выгодополучателя получили T и YES в блоках119–125.

Exchange имеет отдельный дополнительный bridge и импорт настоящих CI receipts; допуск perf05 вручную выполнен через Governor/Timelock в блоках123–143 (proposal, For, queue, execute). Полный browser market lifecycle ещё предстоит. Общая цель остаётся активной: все20сценариев, дополнительные функции и обе стороны settlement ещё не подтверждены во всех трёх реализациях. Старый v3 не подменялся; сертификаты полного Nat-профиля ещё не получены. Для Ix подготовлен [каталог трёх исходных утверждений](imports/ix-starter/README.md): все три прошли Lean/exporter/NanoDa v3 за1.380–3.731s при пике117.9–129.1MiB, импортированы в Agora и вручную проверены как черновики. Их ZK-сертификаты ещё не получены. [Композиция библиотек](research/compositional-lean-environments.md) пока имеет статус проекта архитектуры, не реализации.

Ниже сохранена история начала работ и предшествовавших ограничений.

Начата реализация. Исследовательские ограничения Lean/zk из предыдущей документации проверяются практическим запуском. Ни одна сборка на момент создания этого файла ещё не считается готовой.

Уточнение 2026-09-10: после сообщения о расходе 44 ГБ и сбое приложения приоритетом стали [скорость и память](./performance-and-memory.md). Прежние незавершённые prover остановлены, обычные API запрещают новые тяжёлые запуски до проверки подходящего backend. Отдельные измерительные кандидаты допускаются координатором только последовательно с учётом всего дерева памяти/таймаутом. Agora и Exchange сохранили свои цепи; потерянная временная Hardhat-цепь Vault заменена явно новой Anvil-историей с сохранением и проверенным reload, прежние отчёты архивированы. Все три интерфейса снова доступны. Требование настоящего Lean → zk → onchain остаётся невыполненным и не заменяется кэшем тестового ответа.

Для самого дешёвого сквозного smoke дополнительно готовится отдельный профиль конструктивной логики без аксиом: `∀ P : Prop, P → P` и опровержение `∀ P : Prop, P`. Это настоящие Lean-программы с полной независимой проверкой деклараций в zkVM, а не встроенное сравнение с известным текстом. Профиль имеет собственные image/profile и минимальную pinned foundation `False`; существующий профиль Nat.add_comm не изменяется под старым идентификатором. Пока сертификаты этого кандидата не созданы, это план эксперимента.
