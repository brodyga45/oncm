Исторический аудит ниже сохранён для трассировки. Полнотекстовый onchain social реализован в трёх приложениях; свежие browser/RPC результаты находятся в [onchain-social.md](onchain-social.md) и app evidence. Это заменяет старые offchain social passes. Generic external bundle import реализован и проверен в Agora/Vault, Exchange дорабатывается; настоящий сертификат совершенно новой цели этим не заявляется.

В FALSE-проходе Vault найдены и исправлены два UX-дефекта: старый LP scenario сохранялся после смены кошелька; преждевременное разрешение производного показывало unknown custom error. Повторный browser проход171/177 подтвердил понятное ожидание родителя и очистку/пересчёт для нового кошелька. Дополнительный взнос, частичный выход и вложенные производные пройдены179–188; подробности в Vault evidence выше. Дедлайны, остальные ветки и переносимость пакетов остаются самостоятельными требованиями.

**Самое позднее уточнение пользователя 2026-09-10:** социальный слой и личные блоги должны быть полностью ончейн. Поэтому прежние social passes в этом аудите больше не закрывают целевую реализацию; нужен переход по [onchain-social.md](onchain-social.md) и новые receipts/rebuild checks для всех трёх вариантов. Торговые и доказательные требования сохраняются.

**Более позднее решение пользователя 2026-09-10:** убрать генерацию/заказ новых сертификатов из сайтов текущей версии, пользователи подготавливают сертификаты сами. Поэтому перечисленные ниже gaps remote dispatch/встроенного prover US-017 теперь **отложены и не блокируют текущую приёмку**. Это исторический аудит до изменения объёма: его описание remote как главного blocker больше не актуально. Обязательны готовый внешний сертификат → точная проверка → регистрация/резолв, остальные сценарии, социальные функции и extras. Ограничение импортера двумя fixture goals не следует автоматически считать поддержкой произвольного внешнего сертификата; совместимость импорта и underlying generic onchain bridge проверяются отдельно.

Новые результаты: Exchange вручную допустил perf05 Governor/Timelock в блоках123–143; true-market lifecycle ещё не завершён. Vault прошёл социальные действия с двумя кошельками ([evidence](evidence/vault-social-2026-09-10.json)); дефект reply-order исправлен в коде, ручной повтор после API restart ещё нужен. Agora NO-цикл дошёл до verified CI6 и блока54, финальный резолв остановлен автоматической проверкой разрешений; не считается пройденным.

Срез: 10 сентября 2026 года. Это bounded read-only аудит текущего кода и сохранённых результатов, без нового запуска тестов, браузера, prover или транзакций. Он сохраняет весь объём [20 сценариев](user-scenarios.md), [социальных функций](profiles-and-discussions.md) и двух авторских возможностей каждой реализации. Прохождение одного настоящего рынка не сокращает этот объём.

Главный подтверждённый результат: **Vault и Agora прошли через браузер настоящий perf05 true-цикл**, включая original RISC Zero verification, регистрацию, ликвидность, buy/sell, resolution и redemption. Vault также выплатил protocol income обоим адресам; Agora выплатил LP-комиссию отдельному LP. **Вся задача ещё не завершена.** В частности, сайты пока не отправляют пользовательские задания в удалённый GitHub proving; импорт готового сертификата реализован отдельно. Получены настоящие сертификаты обеих сторон perf05, но полноценный NO-рынок ещё не записан как browser pass во всех трёх приложениях.

## Как читать статус

- **Веб** — конкретное действие действительно выполнено координатором в браузере; для денежных действий есть receipt и исторические балансы. Указанные блоки принадлежат только своей цепи.
- **Тест/API** — сохранённый автоматический или программный результат. Экономические suites используют настоящие AMM/CTF, но отдельный test verifier; они не доказывают настоящий Lean → zk. Нативный Lean check также не является zk.
- **Код** — найден связанный web/SDK/API/contract путь; успешный пользовательский проход не заявлен.
- **Пробел** — отсутствует часть реализации или проверки. В таблицах явно различаются «нужно реализовать» и «нужно пройти».

Не вводится общий зелёный статус US: один US часто содержит основной путь, ветку отказа и восстановление. Тест отказа может закрывать контрактный инвариант, но не подтверждает, что сайт понятно показывает этот отказ. Наличие кнопки не подтверждает её работу.

Авторитетный актуальный журнал — [manual-validation.md](manual-validation.md). Исторические фразы «сертификата ещё нет», «рынков 0» в старых app audit/README/VALIDATION относятся к моменту их записи; они не отменяют более поздние receipts. И наоборот, новые receipts не закрывают автоматически остальные строки старого аудита. [scenario-coverage.md](scenario-coverage.md) — карта требований, не результат исполнения.

## Существенные implementation gaps и зависимости

### 1. US017: удалённое вычисление из приложения ещё не реализовано

Все три owned queues вызывают локальный `proof/runner.mjs`; все три `proof/execution-policy.local.json` содержат `allowExpensiveProving:false`. У Agora/Vault это [server/proof-jobs.mjs](../implementations/agora/server/proof-jobs.mjs) и [Vault adapter](../implementations/vault/server/proof-jobs.mjs); у Exchange [api/proof-jobs.mjs](../implementations/exchange/api/proof-jobs.mjs). Native check доступен; включать тяжёлое proving обратно для «закрытия» строки нельзя.

Работающий удалённый backend существует **на уровне coordinator CI**: [.github/workflows/lean-zk-smoke.yml](../.github/workflows/lean-zk-smoke.yml), [CI runner](../tools/lean-zk/ci/run.py). Его `workflow_dispatch` принимает только `profile: perf05|v3` и один из четырёх `case` либо `all`. Сайты не dispatch-ят workflow, не сопоставляют run с SIWE owner, не показывают remote queue/logs/cancel, не забирают возвращённый artifact автоматически. Root запускал CI отдельно, затем импортировал настоящий результат. Это полезный реально работающий этап, но не полное исходное «нажать в сайте и получить certificate».

Минимальная оставшаяся работа: provider interface для submit/status/cancel/artifacts, immutable input/package digest, owner-bound job ID и retry, server-only ограниченное полномочие доступа к CI, очередь одного heavy job, видимые timeout/cost/privacy rules. Возвращаемый сертификат должен пройти существующую exact binding + original EVM + governed bridge проверку; `evmVerified` из JSON не является доверенным флагом. Отмена/сбой должны сохранять историю и не оставлять child computation. CI secrets не отправляются в web/SDK клиент; package source нельзя автоматически публиковать из чужих private jobs.

Пользователь выбрал бесплатный GitHub CI. Это не требует дальнейшей покупки Boundless/Bonsai; backend capacity/очередь и GitHub limits остаются операционной зависимостью. Выбор GitHub сам по себе не реализует интеграцию с приложениями.

### 2. Generic Lean и fixed perf05 — разные степени покрытия

Настоящий guest проверяет Lean exports; это не текстовый mock. Но текущая доставка certificate имеет ограниченный product envelope: заранее pinned CI source/NDJSON, два known perf05 goals и их четыре artifacts. App external certificate descriptors/importers сверяют именно эти cases. Новый arbitrary theorem не становится поддержанным от того, что у него есть текст `Oncm.goal`.

v3 native runner успешно проверяет конкретные пользовательские wrappers, включая три [Ix examples](imports/ix-starter/README.md), при своих foundation/profile rules. Это подтверждает часть общего ядра, но не получение новых zk receipts/market registration этих целей. v3/Nat.add_comm и Ix ZK ещё не доведены до принятого smoke в данном срезе. Полная композиция Mathlib/внешних библиотек с pinned dependency closure остаётся [архитектурной работой](research/compositional-lean-environments.md), а не обещанной совместимостью любого Lean repository.

Чтобы закрыть general-use requirement: immutable package→целевой declaration→export closure/foundation compatibility→новая registration/proof job→actual receipt→импорт по проверенным metadata, без fixture-only lookup. При неизменном допустимом foundation новый theorem может идти под существующим profile; изменение trusted environment/image требует отдельного profile/governance. Формат и policy надо расширить явно; нельзя просто снять goal allowlist и считать любой source привязанным к certificate.

### 3. US012/013: импорт файлов не равен переносимой проверке

Все три умеют взять публичные материалы exact snapshot и сохранить provenance. Ни одна не подтверждает полный произвольный Palomar→dependencies→Comparator/Lean→zk→settlement. Agora JSON import не проверяет заявленные file hashes — конкретный недостающий validation step. Exchange JSON roundtrip сохраняет материалы, но не доказывает fresh environment reproduction. Vault имеет настоящий минимальный Lake ZIP; всё ещё нужны независимый build/check и сравнение resulting goalHash/profileId с chain context. Загрузка package не даёт ему право выполнять произвольный Lake config без sandbox/ресурсной политики.

Ручной следующий шаг для каждого: экспортировать конкретный настоящий рынок, открыть точные Challenge/Solution/toolchain/lock/metadata, сохранить hashes и проверить в отдельной доверенной среде. Нужные credentials/публичность относятся только к выбранной remote delivery; private source не публикуется по совпадению goalHash. Palomar acceptance/LLM description checks не становятся oracle.

### 4. Независимые UX gaps, не заблокированные отсутствием proof

| Приложение | Конкретный файл/операция | Значение |
|---|---|---|
| Agora | `src/App.vue createMarket` | Resume составного register/createPool/fund после частичного успеха; existing statement должен быть доступен без повторной регистрации. |
| Agora | `src/App.vue importPackage/applyPackage`, package service | Проверка schema/file hashes/goal context перед доверием imported package fields. Imported certificate отдельно проходит crypto check. |
| Agora | `src/App.vue switchRole/startJob` | Injected identity handlers/logout и безопасный poll при отсутствии job нового owner. Это статически найденная ветка, не заявленный новый browser reproduction. |
| Agora | `liquidity/redeem` UI/SDK | LP-return/withdraw/redeem preview, читаемые derived predicate и промежуточные receipts. Контрактные операции уже существуют. |
| Exchange | `web/main.jsx Governance` + governance API views | ETA/quorum/hasVoted/historical weight, персональная доступность действий, небольшой шаг mining. Governor остаётся реальной защитой; UI должен объяснять отказ до отправки. |

Автоматические типизированные формы новых operators, proposal discussions/исторический registry diff и сложный multicall composer — явно оставшиеся удобства. Наличие raw SDK/governed module path нужно учитывать: эти ограничения нельзя смешивать с отсутствием onchain extensibility. Напротив, remote user job и независимая воспроизводимость пакета являются материальной частью исходных сценариев.

## Следующие ручные проходы в порядке зависимостей

1. **Закончить root Exchange truecycle** и добавить фактические receipts. Не сбрасывать ни одну цепь и не создавать тестовый market с mock verifier. Остальные browser строки меняются только по зафиксированным действиям.
2. **Социальный проход и extras без вычислений:** на существующих рынках два кошелька, profile/reply/vote/edit/Top-New, Agora shelf/notebook, Exchange journal/CSV; Vault preflight. LP scenario/arb требуют реальной funded позиции/двух pools и при необходимости отдельных обычных transactions.
3. **Protocol income:** Agora beneficiary PaymentSplitter release; Exchange actual V2 protocol LP mint→collect/distribute/withdraw; Vault account-switch Income retest и old-epoch ветка. Суммы в исходных активах, LP fee не подменяет protocol fee, dust сохраняется явно.
4. **Настоящий NO-cycle во всех трёх:** CI5+CI6 уже снимают криптографический artifact gate для двух fixed perf05 goals. Создать false-goal market, LP/NO trades, verify/submission, payout[0,1], redemption/LP exit, raw blocks/balances. Никакого нового prover для этих готовых artifacts не требуется.
5. **Производные и failure paths:** пока base unresolved, создать ResolvedBy/ResolvedAs/ResolvedAsBy, пройти pending/timely/expired/opposite. Граничное равенство timestamp и некоторые malicious binding случаи можно фиксировать deterministic tests отдельно от браузера. LP partial/additional, refusal limits, winner/loser/repeat, несколько losing beneficiaries, governed operator и права кошелька также отдельные проверки.
6. **US012/013 и general US017:** сначала реализовать gaps пакета/remote job, затем новый компактный публичный Lean theorem (не переименованный perf05 fixture) → подготовка/экспорт→реальное remote proving→EVM→market lifecycle. Первый такой результат и source/profile должны сохраняться переносимо. Более крупные библиотеки/FLT остаются отдельной подтверждаемой capacity/compatibility зависимостью.

Для каждого нового прохода сохранять actor, explicit UI action, statement/profile/condition/pool IDs, block/hash/timestamp, tx/receipt/decoded events и balances до/после, либо owner-bound job/artifact/hash для офчейн-действия. Уже выполненные browser денежные действия не повторять ради красивого списка; используемые старые traces сохранять. Эта таблица является продолжением полной задачи, а не основанием завершить её после базового smoke.
